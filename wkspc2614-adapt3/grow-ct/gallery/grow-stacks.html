grow · the two build stacks

Two stacks, one grow interface

Both stacks keep Adapt's contrib layer (components + extensions) fully functional and plug into Adapt's required structures. They differ only in who owns the mechanical structure. The style tier is shared: one grow-core-less entry that imports a swappable base token layer, a theme template, and finally a customer profile the generator writes.

Mechanical tier — structure / HTML + classes Style tier — LESS / tokens swappable profile-driven, retint/reskin without touching the layer above

adapt-core-base

Adapt owns the structure; Grow owns the styles. The base layer is swappable, so a different base profile reskins your course on Adapt's native structure.

Mechanical — structure
adapt-contrib-core + contrib
core structural HTML + classes; components & extensions stay functional
↓
adapt-core-structure → course shape
the native Adapt tree (page / article / block / component) is emitted
End of mechanical · start of styles
grow-core-less
the one interface entry — @imports the layers below
↓ @import
grow-base-<grouping>base · swappable
token groupings — grow-base-typography, -color, -space…
↓
grow-theme-template
the painting that dresses Adapt's native structure from the tokens
↓
grow-<customer>-theme-profilegenerator output
active profile — the dials, written by the theme generator
Plugins: real adapt-contrib-core + contrib + _theme: grow-ct (styles) + the Grow content kit. Structure = Adapt's.

grow-core-base

Grow adds its own structure on top of Adapt's — custom structural objects, classes and generated HTML — merged into the grow interface that emits the course shape. Same swappable style tier.

Mechanical — structure
adapt-contrib-core + contrib

adapt-core-structure

+

↓ merge
= grow-core-structure

↓
→ THE COURSE SHAPE

grow-core-less

↓ @import
grow-base-<grouping>base · swappable

Plugins: real adapt-contrib-core + contrib + _theme: grow-ct carrying the structural overrides (templates/ + themeBlockView + schema) = grow-core-structure, optionally a custom _menu plugin.
Both packages are assembled under packages/ (README + adapt.json + config.json), and grow-core-base carries the grow/ LESS scaffold with these exact names. Architecture: docs/grow-base-architecture.md. The one invariant: keep Adapt's class/hook contract so core + contrib keep working.
