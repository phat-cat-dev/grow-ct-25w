Adapt DOM map — the frame, and two components inside it

The same page → article → block frame holds any number of components. Here one block holds two: a text component (header partial only) and a card component whose widget is a whole .cm.card object. The frame is fixed; the component widget is where you "go mad".

Provenance. repo confirmed from this project (adapt-abbott-theme LESS, ab-cards.less, flipcard.jsx). core standard adapt-contrib-core v6 inner wrappers / heading nodes, to re-verify against src/core/js. example illustrative markup you would author (a card component is one way; the same .cm.card markup can also live in a text component’s rich-text body).

The component boundary: unlimited vs the contract

Unlimited (below .component__inner)

  • any nested divs, any depth
  • as many class hooks as you like (mycomp__*, is-*)
  • any data-*, any ARIA
  • skip the header partial; render your own
  • sub-components; any JS in postRender (React/D3/canvas)
  • any schema fields → props (e.g. the whole .cm.card object)

Fixed / must keep

  • .component root + state classes (is-complete…) — core-owned
  • completion signal (setReadyStatus, inview)
  • a11y: js-heading aria-level, focus, native controls
  • trackable() / suspend_data for persisted state
  • namespace hooks; consume --ab-* tokens, no hardcoded palette
  • a component is a leaf — can’t reshape article/block
