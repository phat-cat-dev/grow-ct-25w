A little header.
A whole theme.

An isolated version of the studio's floating header. Unlock the colour, try a new source, and save a real studio scheme.

The original studio is unchanged. This model uses its existing API and colour helpers.

Live preview

One source. A consistent surface.

Theme changes are scoped to this workshop, not the document root. Scroll down to see the header stay with you.

01 / Modes

Open Mode using the contrast icon to choose Light, Dark, Contrast or System. No-motion is independent; system reduced-motion preferences are always respected.

02 / Source colour

Unlock to paste an opaque hex, RGB, HSL or named CSS colour. Enter applies it; Escape restores the current colour.

03 / Studio schemes

Open Schemes using the code icon to load, edit and save schemes. Build a scheme into a theme with full CSS and token JSON.

Thinking in React

State first. Markup second.

The working component follows three steps: an event changes state, render reflects state, and the adapter handles external work.

ThemeManager
  ModePreferences    // light / dark / contrast / system + no-motion
  SourceColour       // colour + locked
  SchemeTools        // open + busy + saved schemes

click -> update state -> render -> notify preview

In JSX, class becomes className, click listeners become onClick, and our state updates become useState calls. Keep API requests in the adapter rather than in your button markup.

See the accompanying README for a small JSX conversion exercise and the mounting contract.

Reusable by design

A component, not another global toolbar.

Each instance has unique accessible IDs, its own state, scoped styles and a cleanup function. No React dependency or build step is needed for this first version.

Custom CSS is stored and included in server builds, but is deliberately not injected into this isolated preview. Other loaded studio settings are retained when saving.
